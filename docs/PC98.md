# PC-98 graphics

The PC-98 games draw on hardware that works nothing like a framebuffer of
RGB pixels. The ports keep its model, because the games depend on its
quirks: what one page holds while the other is shown, which bytes a write
touches, and what lies past the visible lines.

## Pages and planes

Graphics are 640x400 pixels in 16 colors. Each color index has four bits,
and each bit lives in its own plane: blue, red, green and intensity. A
plane holds one bit per pixel, eight pixels to a byte with the leftmost in
bit 7, 80 bytes to a row. The 400 rows fill 32000 of a plane's 32768
bytes; the last 768 are never shown but still hold whatever was written.

There are two such pages. The access page is the one that CPU reads and
writes go to; the display page is the one on screen. They are set
independently, so a game draws into one page while the player sees the
other, then swaps them, or keeps a clean background on one page and copies
from it to erase sprites on the other.

`th02/video` holds both pages as color indices, one byte per pixel,
including the hidden tails, with `Video_AccessPage` and `Video_ShowPage`
as the two selectors. Code that the original wrote plane by plane goes
through `Video_ReadPlaneByte` and `Video_WritePlaneByte`, so writes that
run past row 400 land in the tails as they did.

## Palette

The 16 indices map to an analog palette of 4 bits per channel, 4096 colors
in all. Fades and flashes rewrite the palette, not the pixels.

## The graphic charger

Writing one pixel color by hand takes four plane writes. The graphic
charger (GRCG) does it in one: in tile mode it writes a preset color to
all four planes at the masked bits of a byte, and in read-modify-write mode
it keeps the unmasked bits. Most of the games' fills, lines and sprite
erases go through it, and the ports model both modes.

## Scrolling

The display controller starts each frame at a word address of its own and
can split the screen into two regions with different start addresses.
Vertical scrolling moves the start address instead of copying pixels, and
the address wraps within each plane, so a scrolled screen shows the top
rows again below the bottom. `Video_SetSplit` and `Video_ScrollUp` set
those addresses, and `Video_Scanout` reads the pages the way the display
does.

## Text RAM

Over the graphics lies a separate text layer of 80x25 cells, each a
character code with an attribute for color, blink, reverse and underline.
Games draw their HUD and dialogue there. Gaiji are 256 user-defined 16x16
glyphs that the text layer shows like characters; the games load their own
set at start.

## Timing

The 24 kHz display mode the games run in refreshes at about 56.42 Hz, and
the games count frames by its VSync interrupt, not by a timer.
